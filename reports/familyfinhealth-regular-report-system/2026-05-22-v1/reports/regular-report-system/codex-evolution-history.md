# Codex 使用演進歷史

本檔用來每天記錄 Kevin 使用 Codex 之後的工作方式演進：調整過什麼、踩過什麼坑、產生哪些成果，以及哪些經驗可以教給後續夥伴。日期以台灣時間為準。

## 紀錄原則

1. 只記錄可追溯、可教學、可複用的變化，不寫流水帳。
2. 每日先留下素材，週報整理成模式，月報整理成能力，季報整理成策略。
3. 坑洞要寫成「症狀、原因、解法、下次預防」，避免只記錄情緒。
4. 成果要連到具體產出，例如報表、檔案、自動化、網站功能、教學素材或流程改善。
5. 對沒有資訊背景的人，要用任務語言說明，不用工程術語當作主要敘述。
6. 每日也要同步整理 Kevin 的提問與任務敘述回饋，寫入 `kevin-codex-daily-feedback.md`。

## 每日紀錄格式

```text
### YYYY-MM-DD

- 今日 Codex 用法：
- 調整過什麼：
- 踩過什麼坑：
- 解法或新規則：
- 產出成果：
- 可教給夥伴的一句話：
- 證據來源：
```

## 週月季整理規則

| 週期 | 整理重點 | 輸出方式 |
| --- | --- | --- |
| 每日 | 今日用法、調整、坑、成果 | 追加到本檔，並在日報保留「Codex 演進紀錄」摘要 |
| 每週 | 本週學到的工作模式、反覆問題、最有用的提示語 | 寫入週報的「Codex 演進週記」區塊 |
| 每月 | 已穩定下來的流程、可複用模板、教學素材更新 | 寫入月報，並更新教學檔 |
| 每季 | 能複製給團隊的工作系統、角色分工與風險控管 | 寫入季報，整理成夥伴訓練建議 |
| 每日回饋 | Kevin 的提問方式、任務描述、追問品質、可改善處 | 追加到 `kevin-codex-daily-feedback.md`，並在日報保留摘要 |

- 今日 Codex 用法：把既有日報、週報、月報、季報、半年報與年報自動化，延伸成「Codex 使用演進史」與「非資訊背景夥伴教學」的長期系統。

- 解法或新規則：新增本檔作為長期總帳，新增 `codex-nontechnical-partner-teaching.md` 作為夥伴教學主檔，新增 `kevin-codex-daily-feedback.md` 作為每日回饋檔，並把規則寫回自動化提示。

- 可教給夥伴的一句話：不要把 Codex 當成會寫程式的黑盒子，把它當成可以幫你整理任務、提出下一步、留下紀錄的工作夥伴。
