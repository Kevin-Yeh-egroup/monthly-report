Codex 使用演進歷史

每天記錄 Kevin 使用 Codex 之後的工作方式演進：調整、踩坑、解法、成果與可教學素材。日期以台灣時間為準。

紀錄原則

  1. 只記錄可追溯、可教學、可複用的變化，不寫流水帳。
  2. 每日先留下素材，週報整理成模式，月報整理成能力，季報整理成策略。
  3. 坑洞要寫成「症狀、原因、解法、下次預防」。
  4. 成果要連到具體產出，例如報表、檔案、自動化、網站功能、教學素材或流程改善。
  5. 對沒有資訊背景的人，要用任務語言說明，不用工程術語當主軸。
  6. 每日也要同步整理 Kevin 的提問與任務敘述回饋，寫入 kevin-codex-daily-feedback.md。

### YYYY-MM-DD

- 調整過什麼：
- 踩過什麼坑：
- 解法或新規則：
- 產出成果：
- 可教給夥伴的一句話：
- 證據來源：

每日今日用法、調整、坑、成果追加到本檔，並在日報保留「Codex 演進紀錄」摘要
