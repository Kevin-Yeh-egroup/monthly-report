Reporting Process

固定報表流程紀錄

記錄 Kevin 對固定報表流程的要求與變更，避免後續自動化跑偏。

目前原則

  1. 報表要整理成可報告的重點，不做流水帳。
  2. 每日報表必須同時服務「今天怎麼工作」與「昨天營運如何」。
  3. Gmail 統計報告搜尋必須包含 in:anywhere。
  4. 日報歷史在 report-index.html 必須依月份分類。
  5. 獎章與成就紀錄要能被月報、季報、半年報與年報追溯。
  6. Codex 使用演進要獨立記錄，包含每日用法調整、踩坑、解法、成果與可教學素材。
  7. 給沒有資訊背景夥伴的 Codex 教學檔要保持白話、任務導向、可實作。
  8. 每日要根據 Kevin 的提問、任務敘述與追問方式給回饋，指出做得好的地方、可以更清楚的地方與隔天練習。
  9. 是否需要 agent 要先做判斷：清楚的一次性任務可直接處理；長期追蹤、策略、教學、跨工具回顧與成長回饋要納入 agent/反思視角。
  10. 固定報表可走 publish-codex-report，但預設只建立本機 publish-ready 套件；未經 Kevin 批准不得上傳、部署或分享網址。
  11. 資料來源優先級：familyfinhealth 後台 overview、familyfinhealth 後台 trends、Google Ads campaign、Codex/GitHub/Vercel 紀錄是第一順位；信箱摘要是第二順位。
  12. 週報以週日到週六為一週；若同一週橫跨月份，正式週報歷史拆成月內片段。
  13. Kevin 的目標狀態是本機 publish-ready/ 更新後公開 production 站也自動更新；啟用前仍需明確批准，且不得自動處理敏感內容、權限、網域或移除 noindex。
  14. 需要登入的第一順位來源要優先使用 egroup.kevin@gmail.com 的 Chrome Default profile；shell/curl 無登入狀態時不得直接視為後台或 Ads 不可讀。
