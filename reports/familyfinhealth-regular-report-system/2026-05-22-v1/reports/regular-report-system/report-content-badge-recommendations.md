# 報表內容建議與 Kevin 獎章機制

更新日期：2026/05/21

## Websearch 參考依據

- Tableau KPI dashboard 建議先確認目標受眾、目的、KPI、日期比較、資料來源與更新時間，並用趨勢協助決策。來源：https://www.tableau.com/kpi/what-is-kpi-dashboard
- Tableau dashboard 原則提醒不要塞太多資料，應選最相關指標、使用合適圖表、清楚標籤與必要互動。來源：https://www.tableau.com/dashboard/what-is-dashboard
- Microsoft Power BI dashboard design 建議報表要為下一步行動設計，保留 3-5 個關鍵值、提供脈絡、把明細放底部，避免裝飾凌駕判讀。來源：https://nam.powerbi.microsoft.com/en-nz/blog/the-art-and-science-of-effective-dashboard-design/
- Harvard Business School 的 Progress Principle 強調「有意義工作的微小進展」會提升動機與創造力，適合轉化成日報與獎章的核心設計。來源：https://www.hbs.edu/faculty/Pages/item.aspx?num=40244
- Stack Overflow badges 的設計目的是鼓勵有助社群的行為；研究也提醒徽章會引導行為，但取得後可能回落，所以要避免只為徽章刷數字。來源：https://stackoverflow.blog/2021/04/12/stack-overflow-badges-explained/ 與 https://arxiv.org/abs/2008.06125

## 報表內容建議

### 日報

目的：留下每日可回溯的工作與營運紀錄，隔天能直接接續。

建議區塊：

1. 本日主訊息：一句話說今天最大的進展或風險。
2. 本日工作紀錄：查 Git / GitHub / Cursor / Codex / Gmail / 手動補充，整理成 1-4 個主題列點。
3. 核心數據：註冊、訪客、核心工具使用、Google Ads 異常。
4. 異常與原因假設：只列需要追蹤的變化。
5. 明日優先事項：最多 3 件。
6. 今日獎章：用來標記真實進展，不做排名。

### 週報

目的：用於週會與管理溝通。

建議區塊：

1. 本週重點摘要。
2. 本週工作成果地圖。
3. 核心 KPI 與週趨勢。
4. Google Ads 分析。
5. 檢測與工具轉換漏斗。
6. 下週預計工作。
7. 下期優化建議。
8. 本週獎章與累積進展。

### 月報

目的：把每日與週報素材彙整成主題、里程碑與決策。

建議區塊：

1. 月度主結論。
2. 重要里程碑與交付成果。
3. 各工作主題佔比與趨勢。
4. Google Ads 月度效率與預算建議。
5. 產品 / 檢測 / 工具使用趨勢。
6. 風險、阻塞與跨月待辦。
7. 下月優先順序。
8. 月度獎章牆。

## Kevin 獎章機制

設計原則：

- 獎章要獎勵「有意義的進展」，不是單純刷 commit 數。
- 每枚獎章必須有證據來源，例如 Git commit、PR、Codex 對話、Gmail 日報、後台數據或手動補充。
- 不做排行榜。以個人進展、專案推進與可回溯紀錄為主。
- 取得獎章後仍要看下一步行動，避免徽章變成結束點。

### 日報獎章

| 獎章 | 觸發條件 | 證據 |
| --- | --- | --- |
| 今日小勝 | 當日完成至少 1 個可交付工作或明確推進 | Git / Cursor / Codex / 手動補充 |
| 資料偵探 | 找到缺漏資料、修正資料口徑或補齊來源 | Gmail / 後台 / 報表紀錄 |
| 轉換觀察員 | 找出 Ads、訪客、註冊、工具使用間的明確異常 | Google Ads / familyfinhealth |
| 自動化推進 | 報表、skill、agent 或流程自動化有實際改善 | Codex / repo |
| 產品打磨 | 完成使用者可感知的頁面、工具、流程或文案優化 | Git / GitHub / Cursor |

### 週報獎章

| 獎章 | 觸發條件 | 證據 |
| --- | --- | --- |
| 週度交付 | 本週完成跨日、多步驟或可展示成果 | 週報工作地圖 |
| 漏斗修復者 | 本週釐清或改善一段轉換漏斗 | 後台數據 / Ads / 報表 |
| 系統整合者 | 串接多個工具、資料源或工作流程 | Git / Codex / GitHub |
| 研究轉行動 | 把研究、websearch 或 skill 探索轉成可執行流程 | Codex 對話 / 文件 |

### 月報獎章

| 獎章 | 觸發條件 | 證據 |
| --- | --- | --- |
| 月度里程碑 | 完成一個可被管理層理解的月度成果 | 月報里程碑 |
| 長線建設者 | 持續推進自動化、資料系統或產品基礎建設 | 多週紀錄 |
| 成效解讀者 | 能用數據解釋本月成長、下滑或轉換問題 | 月度 KPI / Ads |
| 影響力擴散 | 工作成果影響到課程、網站、工具、報告或團隊流程 | Git / GitHub / 課程 / 報表 |

## 自動化規則

每次產生日報、週報或月報時，Codex 應自動：

1. 查營運資料。
2. 查實際工作紀錄。
3. 產出報表。
4. 根據證據判斷可授予的獎章。
5. 把獎章與理由寫入報表，但只列 1-3 枚，避免喧賓奪主。
6. 把獎章累積到歷史紀錄，月報再彙整成「月度獎章牆」。
