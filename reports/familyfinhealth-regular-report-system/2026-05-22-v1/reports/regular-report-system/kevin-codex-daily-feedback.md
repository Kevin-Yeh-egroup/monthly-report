# Kevin 每日 Codex 使用回饋

本檔根據 Kevin 每天對 Codex 的提問、任務敘述、追問方式與工作結果，整理成每日回饋。目的不是評分，而是幫 Kevin 看見自己怎麼與 AI 協作、哪裡已經進步、哪裡可以問得更清楚，讓 Kevin 與 Codex 一起成長。

## 回饋原則

1. 具體、溫和、可行，不做人格評價。
2. 只根據當天可追溯的提問、任務、對話與產出回饋。
3. 同時寫出做得好的地方與可以更好的地方。
4. 每天最多給 1-3 個練習建議，避免變成壓力清單。
5. 對不足的描述要轉成下一次可嘗試的行為。

## 每日回饋格式

```text
### YYYY-MM-DD

- 今日提問與任務特徵：
- 做得好的地方：
- 可以更清楚的地方：
- 對 Codex/agent 使用的觀察：
- 明日可練習的一件事：
- 一句回饋：
- 證據來源：
```

## Agent 使用判斷規則

| 情境 | 是否需要 agent | 原因 |
| --- | --- | --- |
| 單一文件、單一自動化、範圍清楚 | 通常不需要 | 直接修改與驗證比較快，成本低 |
| 跨日、跨工具、跨資料來源的長期追蹤 | 建議納入 Agent OS 或專門回顧視角 | 需要記憶、歸納與持續回饋 |
| 需要策略、教學、產品、營運多角度判斷 | 建議先做 agent/角色分流 | 可以避免只用單一工程視角處理 |
| 需要長期觀察 Kevin 的提問習慣 | 需要每日教練/反思視角 | 這不是一次性輸出，而是成長紀錄 |
